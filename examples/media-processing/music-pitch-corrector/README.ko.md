# 음정 보정기 예제

이 예제는 model-compose의 `music-pitch-corrector` 컴포넌트를 사용하여 녹음된 보컬에 오프라인 음정 보정을 적용하는 방법을 보여줍니다 — 음정을 감지하고, 각 노트를 곡의 키에 맞춰 스냅한 뒤, 음색을 유지하면서 재합성합니다.

## 개요

보정은 두 단계로 진행되므로 중간에 결과를 확인하거나 편집할 수 있습니다:

1. **plan** — 음정 트랙에서 각 노트의 목표 음정을 정해 보정 곡선(JSON)을 만듭니다. `pitch`만 받고 녹음은 받지 않습니다.
2. **apply** — 곡선을 따라 보컬을 재합성합니다. 녹음(`audio`)과 곡선을 받습니다. plan에서 넘어오는 것은 오직 곡선뿐이며, 오디오 파이프라인에는 암묵적인 것이 없습니다.

기본 `correct-pitch` 워크플로우는 두 단계를 한 번에 실행합니다 (`audio`와 `pitch` 둘 다 필요). 나머지 워크플로우들은 분리된 경로를 보여줍니다 — plan 계열은 곡선을 JSON으로 내보내고, `apply-curve`는 편집된 곡선을 다시 받아 재합성합니다.

`audio`는 언제나 "재합성할 녹음"을 의미하며, 음정 추정 소스로는 쓰이지 않습니다. 음정 추정은 별도 컴포넌트(`music-pitch-estimation`)가 담당하므로, `plan`은 엔진에 무관하며 내장 추정기로 조용히 폴백하지 않습니다.

### 워크플로우

1. **보컬 음정 보정** (기본) — 음정 추정 → 키 감지 → 곡선 계획 → WORLD 재합성 → 반주와 믹스. 노트 목표는 감지된 키에 각 노트를 스냅하여 선택됩니다.
2. **보정 곡선 계획만** — `correct-pitch`와 동일한 경로이되 재합성은 생략; 곡선을 JSON으로 내보내 노트 목표를 수동으로 편집하거나 특정 노트를 건너뛴 뒤 `apply-curve`에 넘길 수 있음
3. **기준 멜로디로 보컬 음정 보정** — 보컬과 함께 멜로디 파일(`.mid`, `.midi`, `.xml`, `.musicxml`, `.mxl`)을 업로드. `music-score-loader`가 노트를 추출하고, 보컬에 음정 추정을 돌린 뒤, 각 노트를 대응되는 기준 노트에 스냅, WORLD로 재합성, 반주와 믹스. 곡의 의도된 멜로디(수작업 MIDI, 악보 편집기 출력 등)가 있을 때 각 노트를 가장 가까운 스케일 음이 아닌 **대응되는 기준 노트**에 매핑하고 싶을 때 사용
4. **기준 멜로디 기반 곡선 계획만** — 동일한 멜로디 로딩 경로이되 재합성 없이 곡선을 JSON으로 출력하여 수작업 편집 가능
5. **편집된 곡선 적용** — 편집된 `plan-only` 또는 `plan-with-melody` 곡선으로 보컬을 재합성하여, 곡선 편집이 실제 결과에 반영되게 함

## 준비사항

### 필수 요구사항

- model-compose가 설치되어 PATH에서 사용 가능
- Python 의존성은 첫 실행 시 자동 설치:
  - `pyworld`, `librosa`, `numpy`, `soundfile` (`world` 드라이버가 사용)
- `pyworld`는 플랫폼에 사전 빌드된 wheel이 없으면 소스에서 빌드하므로 C 컴파일러가 필요합니다.

### 설정

이 예제 디렉토리로 이동:
```bash
cd examples/media-processing/music-pitch-corrector
```

## 실행 방법

1. **서비스 시작:**
   ```bash
   model-compose up
   ```
   첫 시작 시 `pyworld`, `librosa` 등을 설치하므로, `pyworld`가 sdist에서 컴파일되어야 할 경우 1분 정도 걸릴 수 있습니다.

2. **Web UI 열기:**
   `http://localhost:8081`에 접속해 워크플로우를 선택합니다. 기본 폼은 보컬 파일과 반주 파일을 받습니다.

3. **API 직접 호출:**
   ```bash
   curl -X POST http://localhost:8080/api/workflows/runs \
        -F vocal=@vocal.wav \
        -F accompaniment=@backing.wav \
        -F strength=0.8
   ```

## 보정 동작

알고리즘 튜닝은 `params:` 아래에 있습니다 (기본값은 합리적이며 필요에 따라 재정의):

- **params.strength** — 각 노트를 목표 쪽으로 얼마나 끌어당길지. `1.0`은 완전 보정, `0.6`은 음색을 어느 정도 남김
- **params.retune_speed** — 불린 노트가 목표에 도달하는 속도. `0ms`는 로봇 같은 Auto-Tune 효과, `40ms`~`80ms`는 자연스러움
- **params.tolerance_cents** — 목표에서 이 센트 이내의 노트는 그대로 둠. 표현력 있는 노래에서는 올리고, 타이트한 스튜디오 테이크에서는 낮춤
- **params.preserve_vibrato** — 노트 중심 음정만 옮기고 노트 내부의 흔들림을 유지. 비활성화하면 모든 것을 목표로 평탄화

## 곡선 포맷

`plan`이 내는 곡선은 두 부분으로 구성됩니다: `notes` 배열 (감지된 노트마다 한 항목)과 `frames` 블록 (프레임별 조밀 배열). `plan`과 `apply` 사이에 JSON을 직접 편집하여 개별 노트를 재정의할 수 있습니다 — `target_pitch`를 바꾸거나, `target_pitch: null`로 노트를 그대로 두거나, 노트를 완전히 삭제해 원래 음정을 유지하는 식입니다.

## 알려진 한계

- 재합성된 숨소리와 거친 발성은 원본보다 약간 매끈하게 들릴 수 있습니다. 질감을 되살리고 싶다면 보정된 구간 아래에 원본을 섞으세요.
- 코드 보컬 (한 마이크에 두 가수)은 지배적인 음정으로 압축됩니다 — 이 컴포넌트는 단선율을 전제합니다.
- 기준 멜로디 파일은 MIDI와 MusicXML을 지원합니다. 다른 포맷(ABC, MEI, Guido 등)은 미구현이니 변환기를 거치거나 미리 구축한 노트 리스트를 넘기세요.
