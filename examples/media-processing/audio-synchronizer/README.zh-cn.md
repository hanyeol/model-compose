# 音频同步器示例

此示例演示 `audio-synchronizer` 组件，用于计算共享相同底层音频的多个录音之间的时间偏移（多机位拍摄、镜像流，或同一事件在不同设备上的录制）。

组件通过 ffmpeg 将每个源解码为单声道 PCM，然后以第一个源为参考执行基于 FFT 的互相关。它为每个输入返回一个 `{offset, confidence}` 项，并以最晚开始的源为锚点重新对齐，使每个报告的偏移都表示需要从该源的头部裁剪多少秒才能到达共同起点。

## 概述

基于 `audio-synchronizer` 组件提供一个工作流：

- **Align Recordings**：为一组录音以最晚开始的录音为锚点计算每个录音的偏移。

组件可互换接受视频或音频源；解码过程中会丢弃任何视频轨道。

## 准备工作

### 前置条件

- 已安装 model-compose 并在 PATH 中可用
- 已安装 [ffmpeg](https://ffmpeg.org/) 并在 PATH 中可用
- 已安装 `numpy`（`pip install numpy`）

### 设置

进入此示例目录：
```bash
cd examples/media-processing/audio-synchronizer
```

确认 ffmpeg 已安装：
```bash
ffmpeg -version
```

## 运行方式

1. **启动服务：**
   ```bash
   model-compose up
   ```

   服务将启动：
   - API 端点：http://localhost:8080/api
   - Web UI：http://localhost:8081

2. **运行工作流：**

   **使用 Web UI：**
   - 打开 Web UI：http://localhost:8081
   - 上传录音（音频或视频）
   - 点击 "Run Workflow"

   **使用 CLI：**
   ```bash
   model-compose run --input '{
     "sources": [
       "/path/to/camera-a.mp4",
       "/path/to/camera-b.mp4",
       "/path/to/camera-c.mp4"
     ]
   }'
   ```

   **使用 API：**
   ```bash
   curl -X POST http://localhost:8080/api/workflows/runs \
     -F "sources=@/path/to/camera-a.mp4" \
     -F "sources=@/path/to/camera-b.mp4" \
     -F "sources=@/path/to/camera-c.mp4"
   ```

## 组件详情

### 音频同步器组件

- **类型**：`audio-synchronizer`
- **驱动**：`ffmpeg`
- **用途**：使用对 ffmpeg 解码后 PCM 的 FFT 互相关，估计共享相同音频的多个录音之间的时间偏移。

每个源在互相关之前会被解码为 8 kHz 单声道 PCM——该采样率既保留了语音/音乐瞬态所需的带宽,又能显著降低 FFT 成本。互相关峰值周围的抛物线插值恢复了亚采样精度,因此报告的偏移不受限于 1/8000 s。

同时接受视频与音频源。解码器会丢弃任何视频轨道,因此同一事件的 `.mp4` 与 `.wav` 录音可以直接互相对齐,无需预处理。

#### 关键字段

| 字段 | 类型 | 必填 | 默认值 | 描述 |
|-------|------|----------|---------|-------------|
| `sources` | 媒体源列表 | 是 | - | 待对齐的录音;第一个作为互相关参考 |
| `batch_size` | 整数 | 否 | 全部源 | 并行解码的源数量 |

#### 输出

该动作返回与 `sources` 相同顺序的 `{offset, confidence}` 项列表。偏移以最晚开始的源为锚点:该源报告 `offset = 0.0`,其余源报告需要从各自头部裁剪多少秒才能到达共同起点。所有偏移因此都 `>= 0`,可以直接送入下游 clipper。

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `offset` | 浮点数(秒) | 从该源起始处裁剪的秒数,使其与最晚开始的源对齐。锚点自身为 `0.0` |
| `confidence` | 浮点数 0..1 | 相对第一个源(用作互相关参考)的归一化峰值相关系数。接近 1.0 表示匹配干净;接近 0 表示两段录音很可能未共享相同音频 |

三台摄像机的输出示例(摄像机 A 是互相关参考,但摄像机 B 最晚开始并成为锚点):

```json
[
  { "offset": 1.2345, "confidence": 1.000 },
  { "offset": 0.0000, "confidence": 0.987 },
  { "offset": 1.7345, "confidence": 0.972 }
]
```

解读:摄像机 B 最晚开始,因此作为共同原点。摄像机 A 必须裁掉前 1.2345 s,摄像机 C 必须裁掉前 1.7345 s,才能与摄像机 B 对齐。

## 工作流详情

### Align Recordings

**描述**:为任意数量的录音以最晚开始的录音为锚点计算偏移。

#### 输入参数

| 参数 | 类型 | 必填 | 描述 |
|-----------|------|----------|-------------|
| `sources` | 文件列表 | 是 | 待对齐的录音。输出中保留顺序;锚点自动选择 |

#### 输出

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `offsets` | 列表 | 每个源一个 `{offset, confidence}` 项,按输入顺序排列。`offset` 是从该源头部裁剪以到达共同起点的秒数 |

## 提示

- **锚点自动选择**:最晚开始的录音成为共同原点(`offset = 0`);其余录音报告非负的头部裁剪量。输入顺序仅决定返回列表的排布。
- **应用偏移**:下游 `audio-clipper` 或 `video-clipper` 从每个源的起始处裁剪 `offset` 秒即可对齐到共同时间线——无需符号判断或填充。
- **第一个源驱动相关性,而非锚点**:第一个源用作 FFT 步骤的互相关参考,因此其 confidence 始终为 `1.0`。这并不意味着它是时间线锚点。
- **Confidence 阈值**:真实世界匹配通常落在 ~0.5 以上。低于 ~0.2 通常意味着两段录音实际上并未共享相同音频——将这些偏移视为不可靠。
- **音频与视频混用**:视频容器会自动解码为音频,因此 `.mp4`、`.mov`、`.wav`、`.mp3` 文件可以在一个 `sources` 列表中自由混合。
- **长度差异**:录音无需长度相同。互相关会扫描两者之间所有 lag,因此一段 30 分钟的录音可以与事件中段一段 5 分钟的录音对齐。
- **时钟漂移**:组件每个源只报告一个偏移,并假设各录音时钟以相同速率运行。廉价硬件的长时录音每小时可能漂移数十毫秒——若漂移重要,请拆分为较短片段并分别对齐。
- **静音与重复**:如果参考的某段没有独特内容(长静音、重复节拍),相关峰值可能落在错误的模式副本上。优先对齐包含清晰瞬态(拍掌、关门声、说话词)的时刻。

## 故障排除

### 常见问题

1. **找不到 ffmpeg**:确认已安装 ffmpeg 并在 `PATH` 中可用。
2. **缺少 `numpy`**:同步器使用 numpy 进行 FFT 相关计算。使用 `pip install numpy` 安装。
3. **所有 confidence 都很低(< 0.2)**:录音很可能未共享相同音频,或其中一段是静音。在信任偏移之前请先用耳朵确认源。
4. **意外的源报告 offset = 0**:该源就是最晚开始的那一个——共同起点锚点。若希望其他源作为锚点,可重新排列输入(且该源必须确实最晚开始,数字才有意义)或在外部对齐。
5. **Confidence 很高但偏移误差达数秒**:重复模式(节拍器、循环 jingle)可能在错误 lag 上产生较强的次峰。请提供包含唯一瞬态的片段,或裁剪到变化更多的区段。
6. **长录音感觉很慢**:每个源在互相关前会被端到端解码。对于数小时的文件,请预先裁剪到实际需要对齐的区域——通常 1 分钟的共享音频就足够。
