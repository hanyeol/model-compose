# Audio Processor MCP 서버 예제

로컬 오디오 처리 파이프라인을 **stdio** 트랜스포트 기반 MCP 서버로 노출하는 예제입니다. 각 워크플로우는 MCP 툴로 등록되며, base64로 인코딩된 오디오 클립을 입력받아 DSP 이펙트를 적용한 뒤 WAV 바이트 스트림으로 반환합니다.

## 개요

`audio-processor` 컴포넌트 기반의 20개 오디오 처리 워크플로우를 제공합니다. 포맷 변환, 필터링, EQ, 다이나믹스, 톤 셰이핑, 공간감, 라우드니스 제어, 에지 처리까지 커버합니다:

**포맷 & 필터**
1. **리샘플**: 샘플레이트 변환 (예: 32 kHz 모델 출력을 44.1 kHz로 정렬)
2. **하이패스 필터**: 컷오프 이하의 저역대(럼블, 험, 초저역 노이즈) 제거
3. **로우패스 필터**: 컷오프 이상의 고역대(히스, 치찰음) 제거

**파라메트릭 EQ**
4. **벨 EQ**: 중심 주파수 주변을 종 모양으로 부스트/컷 (섬세한 톤 조정)
5. **로우 셸프 EQ**: 코너 주파수 이하를 통째로 부스트/컷 (저역 따뜻함 또는 얇게 다듬기)
6. **하이 셸프 EQ**: 코너 주파수 이상을 통째로 부스트/컷 (에어, 광택, 히스 완화)

**피치**
7. **피치 시프트**: 재생 길이는 유지한 채 반음 단위로 피치 이동

**다이나믹스**
8. **다이나믹 컴프레서**: 큰 소리는 눌러주고 작은 소리는 들리도록 다이내믹 축소
9. **노이즈 게이트**: 임계값 이하 신호를 감쇠해 조용한 구간의 노이즈 플로어 정리

**톤 / 컬러**
10. **디스토션**: 크리에이티브 이펙트로서의 강한 하모닉 왜곡
11. **새추레이션**: 청감상 왜곡 없이 미묘한 하모닉 색채와 따뜻함 추가

**공간**
12. **리버브**: 공간감(룸, 홀) 추가

**라우드니스 (정규화)**
13. **정규화 (RMS)**: 목표 RMS 레벨과 피크 상한에 맞춰 볼륨 정규화
14. **정규화 (Peak)**: 최대 피크가 목표 dBFS에 오도록 스케일링
15. **정규화 (LUFS)**: ITU-R BS.1770 기반 통합 라우드니스 목표치에 맞추고 트루피크 보호까지 적용

**라우드니스 (피크 리미팅)**
16. **피크 리미트 (Hard)**: 헤드룸 안전을 위한 브릭월 클리핑
17. **피크 리미트 (Smooth)**: 룩어헤드 리미터로 투명한 마스터링급 피크 제어

**에지**
18. **무음 정리**: 뒷부분 무음과 과도하게 긴 내부 무음 구간 정리
19. **페이드 인**: 시작 부분에 코사인 페이드 인 적용
20. **페이드 아웃**: 끝 부분에 코사인 페이드 아웃 적용

**stdio** 기반이므로 장기 실행되는 HTTP 서버가 아니라, MCP 클라이언트(예: Claude Desktop)가 필요할 때 프로세스를 직접 띄워 사용하는 방식으로 설계되어 있습니다.

## 사전 준비

### 필수 조건

- Python 3.10 이상
- model-compose가 설치되어 PATH에 등록되어 있어야 합니다
- `audio-processor` 컴포넌트 드라이버 의존성 (model-compose 설치 시 함께 설치됨)

### 환경 설정

이 예제는 완전히 로컬에서 동작하므로 환경 변수나 API 키 설정은 필요 없습니다.

## 실행 방법

### stdio MCP 서버로 실행 (일반적인 사용법)

MCP 클라이언트에서 다음과 같이 서버를 등록합니다:

```json
{
  "mcpServers": {
    "audio-processor": {
      "command": "model-compose",
      "args": ["up"],
      "cwd": "/절대/경로/examples/mcp-servers/audio-processor-mcp"
    }
  }
}
```

클라이언트가 이 디렉토리에서 `model-compose up`을 실행하고, 프로세스는 표준 입출력으로 MCP 프로토콜을 처리합니다. 20개 워크플로우가 모두 툴로 노출됩니다.

### CLI에서 단일 워크플로우 실행

MCP 서버를 띄우지 않고 워크플로우를 직접 호출할 수도 있습니다. 오디오 입력은 base64 문자열로 전달합니다:

```bash
# 200 Hz 하이패스 필터
model-compose run highpass --input '{
  "audio": "<base64-인코딩된-wav>",
  "cutoff": 200
}'

# 피치를 2반음 올리기
model-compose run pitch-shift --input '{
  "audio": "<base64-인코딩된-wav>",
  "semitones": 2
}'

# -14 LUFS로 라우드니스 정규화 (스트리밍 타깃)
model-compose run normalize-lufs --input '{
  "audio": "<base64-인코딩된-wav>",
  "level": -14
}'
```

### 스모크 테스트 실행

stdio 서버를 띄우고 툴 목록을 조회한 뒤 1초짜리 사인파로 각 워크플로우를 호출하는 자체 완결형 테스트가 포함되어 있습니다:

```bash
python smoke.py
```

## 컴포넌트 상세

### Audio Processor 컴포넌트
- **ID**: `audio`
- **타입**: `audio-processor`
- **역할**: 포맷 변환, 필터링, 파라메트릭 EQ, 다이나믹스, 톤 셰이핑, 공간감, 라우드니스 정규화, 피크 리미팅, 에지 처리를 아우르는 로컬 DSP 파이프라인
- **액션**: `resample`, `highpass`, `lowpass`, `bell`, `low-shelf`, `high-shelf`, `pitch-shift`, `compressor`, `noise-gate`, `distortion`, `saturation`, `reverb`, `normalize-rms`, `normalize-peak`, `normalize-lufs`, `peak-limit-hard`, `peak-limit-smooth`, `trim-silence`, `fade-in`, `fade-out`

## 워크플로우 상세

### "Resample Audio" 워크플로우

**설명**: 오디오를 다른 샘플레이트로 변환합니다.

| 파라미터 | 타입 | 필수 | 기본값 | 설명 |
|----------|------|------|--------|------|
| `audio` | audio (base64) | 예 | - | base64로 인코딩된 입력 오디오 |
| `sample_rate` | number | 아니오 | `44100` | 목표 샘플레이트(Hz) |

### "Apply Highpass Filter" 워크플로우

**설명**: 컷오프 이하의 저역대를 제거합니다.

| 파라미터 | 타입 | 필수 | 기본값 | 설명 |
|----------|------|------|--------|------|
| `audio` | audio (base64) | 예 | - | base64로 인코딩된 입력 오디오 |
| `cutoff` | number | 아니오 | `80` | 컷오프 주파수(Hz) |

### "Apply Lowpass Filter" 워크플로우

**설명**: 컷오프 이상의 고역대를 제거합니다.

| 파라미터 | 타입 | 필수 | 기본값 | 설명 |
|----------|------|------|--------|------|
| `audio` | audio (base64) | 예 | - | base64로 인코딩된 입력 오디오 |
| `cutoff` | number | 아니오 | `8000` | 컷오프 주파수(Hz) |

### "Apply Bell EQ" 워크플로우

**설명**: 중심 주파수 주변을 종 모양으로 부스트하거나 컷합니다.

| 파라미터 | 타입 | 필수 | 기본값 | 설명 |
|----------|------|------|--------|------|
| `audio` | audio (base64) | 예 | - | base64로 인코딩된 입력 오디오 |
| `frequency` | number | 아니오 | `3000` | 벨의 중심 주파수(Hz) |
| `gain` | number | 아니오 | `0` | 중심 주파수에서의 게인(dB). 양수는 부스트, 음수는 컷 |
| `q` | number | 아니오 | `0.707` | 벨의 폭. Q가 클수록 좁은 대역 |

### "Apply Low-Shelf EQ" 워크플로우

**설명**: 코너 주파수 이하의 대역 전체를 부스트하거나 컷합니다.

| 파라미터 | 타입 | 필수 | 기본값 | 설명 |
|----------|------|------|--------|------|
| `audio` | audio (base64) | 예 | - | base64로 인코딩된 입력 오디오 |
| `frequency` | number | 아니오 | `150` | 셸프 코너 주파수(Hz) |
| `gain` | number | 아니오 | `0` | 셸프 게인(dB). 양수는 부스트, 음수는 컷 |
| `q` | number | 아니오 | `0.707` | 셸프의 기울기. Q가 클수록 코너가 가팔라짐 |

### "Apply High-Shelf EQ" 워크플로우

**설명**: 코너 주파수 이상의 대역 전체를 부스트하거나 컷합니다.

| 파라미터 | 타입 | 필수 | 기본값 | 설명 |
|----------|------|------|--------|------|
| `audio` | audio (base64) | 예 | - | base64로 인코딩된 입력 오디오 |
| `frequency` | number | 아니오 | `10000` | 셸프 코너 주파수(Hz) |
| `gain` | number | 아니오 | `0` | 셸프 게인(dB). 양수는 부스트, 음수는 컷 |
| `q` | number | 아니오 | `0.707` | 셸프의 기울기. Q가 클수록 코너가 가팔라짐 |

### "Apply Pitch Shift" 워크플로우

**설명**: 길이는 유지한 채 반음 단위로 피치를 이동합니다.

| 파라미터 | 타입 | 필수 | 기본값 | 설명 |
|----------|------|------|--------|------|
| `audio` | audio (base64) | 예 | - | base64로 인코딩된 입력 오디오 |
| `semitones` | number | 아니오 | `0` | 이동할 반음 수. 양수는 올리고 음수는 내림 |

### "Apply Dynamic Range Compressor" 워크플로우

**설명**: 큰 소리는 누르고 작은 소리는 들리도록 다이내믹을 축소합니다.

| 파라미터 | 타입 | 필수 | 기본값 | 설명 |
|----------|------|------|--------|------|
| `audio` | audio (base64) | 예 | - | base64로 인코딩된 입력 오디오 |
| `threshold` | number | 아니오 | `-20` | 압축이 시작되는 임계값(dB) |
| `ratio` | number | 아니오 | `4` | 압축 비율 (예: 4는 4:1) |

### "Apply Noise Gate" 워크플로우

**설명**: 임계값 이하 신호를 감쇠해 조용한 구간에 낀 노이즈 플로어와 코덱 아티팩트를 정리합니다.

| 파라미터 | 타입 | 필수 | 기본값 | 설명 |
|----------|------|------|--------|------|
| `audio` | audio (base64) | 예 | - | base64로 인코딩된 입력 오디오 |
| `threshold` | number | 아니오 | `-40` | 게이트가 감쇠를 시작하는 임계값(dB) |
| `ratio` | number | 아니오 | `10` | 다운워드 확장 비율. 클수록 더 공격적 |

### "Apply Distortion" 워크플로우

**설명**: 크리에이티브 이펙트로서 강한 하모닉 왜곡을 추가합니다.

| 파라미터 | 타입 | 필수 | 기본값 | 설명 |
|----------|------|------|--------|------|
| `audio` | audio (base64) | 예 | - | base64로 인코딩된 입력 오디오 |
| `drive` | number | 아니오 | `25` | 드라이브 양(dB). 일반적으로 15~40 |

### "Apply Saturation" 워크플로우

**설명**: 청감상 왜곡 없이 미묘한 하모닉 색채와 따뜻함을 추가합니다.

| 파라미터 | 타입 | 필수 | 기본값 | 설명 |
|----------|------|------|--------|------|
| `audio` | audio (base64) | 예 | - | base64로 인코딩된 입력 오디오 |
| `drive` | number | 아니오 | `3` | 드라이브 양(dB). 일반적으로 1~8 |

### "Apply Reverb" 워크플로우

**설명**: 공간감을 부여하는 잔향을 추가합니다.

| 파라미터 | 타입 | 필수 | 기본값 | 설명 |
|----------|------|------|--------|------|
| `audio` | audio (base64) | 예 | - | base64로 인코딩된 입력 오디오 |
| `room_size` | number | 아니오 | `0.5` | 룸 사이즈 (0.0~1.0) |
| `damping` | number | 아니오 | `0.5` | 고역 감쇠 (0.0~1.0) |
| `wet_level` | number | 아니오 | `0.33` | Wet 신호 레벨 (0.0~1.0) |

### "Normalize Loudness (RMS)" 워크플로우

**설명**: 목표 RMS 레벨과 피크 상한에 맞춰 볼륨을 정규화합니다. 본격적인 라우드니스 미터가 과할 때 소스 간 정렬 용도로 적합합니다.

| 파라미터 | 타입 | 필수 | 기본값 | 설명 |
|----------|------|------|--------|------|
| `audio` | audio (base64) | 예 | - | base64로 인코딩된 입력 오디오 |
| `level` | number | 아니오 | `-20` | 목표 RMS 레벨(dBFS) |
| `peak_limit` | number | 아니오 | `0.85` | 정규화 후 피크 진폭 상한 (0.0~1.0) |

### "Normalize Loudness (Peak)" 워크플로우

**설명**: 최대 피크가 목표 dBFS에 오도록 오디오를 스케일링합니다. 체감 라우드니스보다 헤드룸 확보가 중요할 때 사용합니다.

| 파라미터 | 타입 | 필수 | 기본값 | 설명 |
|----------|------|------|--------|------|
| `audio` | audio (base64) | 예 | - | base64로 인코딩된 입력 오디오 |
| `level` | number | 아니오 | `-1` | 목표 피크 레벨(dBFS) |

### "Normalize Loudness (LUFS)" 워크플로우

**설명**: ITU-R BS.1770 기준 통합 라우드니스 목표치(LUFS)에 맞추고 트루피크 보호까지 적용합니다. 스트리밍/방송 딜리버리에 사용합니다.

| 파라미터 | 타입 | 필수 | 기본값 | 설명 |
|----------|------|------|--------|------|
| `audio` | audio (base64) | 예 | - | base64로 인코딩된 입력 오디오 |
| `level` | number | 아니오 | `-14` | 목표 통합 라우드니스(LUFS). 스트리밍은 -14, 펀치가 필요한 마스터는 -9~-12 |
| `true_peak_ceiling` | number | 아니오 | `-1` | 라우드니스 게인 후 적용할 트루피크 실링(dBTP) |

### "Apply Peak Limit (Hard)" 워크플로우

**설명**: 브릭월 클리핑으로 피크 진폭을 잘라냅니다. 빠르고 저렴한 헤드룸 안전장치이지만 트랜지언트가 많은 소재에서는 왜곡이 들릴 수 있습니다.

| 파라미터 | 타입 | 필수 | 기본값 | 설명 |
|----------|------|------|--------|------|
| `audio` | audio (base64) | 예 | - | base64로 인코딩된 입력 오디오 |
| `level` | number | 아니오 | `0.95` | 피크 진폭 상한 (0.0~1.0) |

### "Apply Peak Limit (Smooth)" 워크플로우

**설명**: 룩어헤드 리미터로 부드럽게 릴리즈하며 피크를 제어합니다. 마스터링급 투명한 피크 제어에 사용합니다.

| 파라미터 | 타입 | 필수 | 기본값 | 설명 |
|----------|------|------|--------|------|
| `audio` | audio (base64) | 예 | - | base64로 인코딩된 입력 오디오 |
| `level` | number | 아니오 | `-1` | 실링(dBFS) |
| `release` | duration | 아니오 | `100ms` | 릴리즈 타임 (예: `100ms`) |

### "Trim Trailing Silence" 워크플로우

## MCP 서버 연동

### 연결 정보
- **트랜스포트**: stdio
- **실행 명령**: `model-compose up` (이 예제 디렉토리에서 실행)
- **프로토콜**: Model Context Protocol v1.0

### 사용 가능한 툴

- `lowpass`

- `high-shelf`
- `pitch-shift`

## 문제 해결

### 자주 발생하는 문제

1. **툴 호출이 오디오 대신 `TextContent`를 반환합니다**: `model-compose` 내부에서 워크플로우가 실패한 경우입니다. `model-compose up`을 stdio 클라이언트 없이 직접 실행해 트레이스백을 확인하세요.
2. **`audio requires raw audio bytes, got str` 오류**: `model-compose.yml`의 `audio` 변수 선언에 `;base64` 디코더 힌트가 붙어 있는지(`as audio;base64`) 확인하세요.
3. **MCP 클라이언트가 서버를 찾지 못합니다**: MCP 설정의 `cwd`는 반드시 이 예제 디렉토리의 절대 경로여야 합니다.
4. **스모크 테스트가 멈춥니다**: `model-compose`가 `PATH`에 등록되어 있는지, 다른 프로세스가 stdio를 점유하고 있지 않은지 확인하세요.
